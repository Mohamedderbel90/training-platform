# Documentation Map

Where each document lives, what it is for, and how it relates to the others.
The five `.docx` sources are approved historical inputs and are intentionally
not edited; where they conflict with newer decisions, `DECISIONS.md` and
`REQUIREMENTS_ALIGNMENT.md` say which text governs.

| Document | Purpose | Use it when |
|---|---|---|
| `BRD_*.docx` | Business requirements (FR, BR, NFR, AC, D-decisions, KPIs); approved 2026-10-03 (DEC-46) | deciding whether something is wanted |
| `SRS_*.docx` | Detailed behaviour per requirement | writing behaviour and tests |
| `ERD_*.docx` | Business data model, constraints, security groups | changing schema or access rules |
| `API_Contract_*.docx` | Operational API intent | integrating Next.js and Odoo |
| `UI_Flow_*.docx` | Odoo menus/screens and Next.js screen intent | building or reviewing a screen |
| `PROJECT_SPEC_v1.1_BILINGUAL.md` | Implementation source of truth: architecture, canonical names, routes, API list | before any code change |
| `DEVELOPMENT_PLAN_v1.1_BILINGUAL.md` | Milestones M0-M10 (delivered) | planning follow-up work |
| `docs/DECISIONS.md` | Business decisions that settle conflicts and gaps (DEC-xx), follow-ups, still-open items | any ambiguity between documents |
| `docs/REQUIREMENTS_ALIGNMENT.md` | Document authority, version-label decoder, superseded references, analysis behind the decisions | deciding which document governs |
| `docs/TRACEABILITY.md` | BRD -> SRS -> ERD -> API -> UI -> code chain, acceptance criteria | release checks, impact analysis |
| `docs/SURVEY_QUESTIONS.md` | Approved wording of the three daily survey sets; loaded by `scripts/seed_surveys.py` | changing or reloading the questions |
| `docs/HELP_PRIVACY.md` | Approved Help, Contact, Terms and Privacy texts (active in the app) | changing those pages |
| `docs/adr/ADR-001` to `ADR-011` | Why technical decisions were made (append-only) | understanding a design choice |
| `docs/RUNBOOK.md` | Deployment, backup, monitoring | go-live and operations |
| `README.md` (root) | Setup, commands, runtime notes, verified runtime deviations | day one |
| `docs/archive/MILESTONE_LOG.md` | Historical M5-M10 delivery narrative moved out of the root README; superseded where it disagrees with the ADRs or DECISIONS | history only |
| `design/` | Approved prototype export (`Main.dc.html`; a reference mockup, not production code; serve the folder to view it) and `UI_UX_DESIGN_SPEC.md` | visual fidelity |
| `noor-login/` | Approved login references and assets; the extracted images are approximate (upscaled photo, strips with a light background), so use `approved-login-reference.png` only for comparison. The images used by the app live in `frontend/public/noor-login/` | login visuals |
| `CLAUDE.md` | Working rules for AI agents (architecture boundaries, source-of-truth order, testing) | automated agents |
| `.claude/agents/*.md` | Role instructions for the specialist agents; each defers to `CLAUDE.md` and this index | automated agents |
| `frontend/AGENTS.md`, `frontend/CLAUDE.md` | Generated by Next.js (`next dev`); read the bundled Next.js docs before frontend code | automated agents |

This file is the only documentation index; the root README and `CLAUDE.md` point here.

Precedence: BRD for business intent; `DECISIONS.md` for settled ambiguities;
`PROJECT_SPEC` for implementation; an ADR that says it supersedes a passage.
